# 브라우저 통합 검증 절차와 기록 양식

이 문서는 사람이 데스크톱 브라우저에서 게임을 직접 플레이하며 확인하는 절차와 빈 기록 양식입니다. 이 문서는 검증 결과가 아닙니다. 아래 기록란이 채워지고 증거가 첨부되기 전에는 어떤 항목도 통과로 보지 않습니다.

자동 규칙 테스트(`node --test`)는 `docs/js/rules.mjs`만 검사합니다. 렌더링·Pointer Lock·마우스 조준·파티클·효과음·실제 시간 흐름은 이 문서의 절차로만 확인합니다.

## 1. 작성 규칙

### 1.1 기록을 만들고 제출하는 방법

1. 이 파일을 저장소 작업 트리 **밖**에 복사합니다. 예: `~/gun-shooter-verification/browser-verification-<SHA 앞 12자리>-<YYYYMMDD>.md`.
   작업 트리 안에 기록이나 증거 파일을 만들면 `git status --short` 결과가 바뀌어 대상 revision과 일치하는지 판단하기 어렵습니다.
2. 증거 파일(스크린샷·영상·콘솔 로그·HAR)은 같은 폴더에 두고, 기록란에 파일 이름과 영상의 시각(예: `round1.mp4 00:42`)을 적습니다.
3. 기록 파일과 증거 폴더를 검증을 요청한 사람에게 직접 제출합니다. PR 설명 자동 수정이나 서버의 후처리를 기대하지 않습니다.

### 1.2 상태 값

| 상태 | 의미 |
| --- | --- |
| 통과 | 조작을 실제로 수행했고, 예상 결과를 모두 관측했으며, 증거 참조를 적었습니다. |
| 실패 | 조작을 수행했으나 예상 결과와 다른 점이 하나 이상 있습니다. 실제 관측란에 차이를 적습니다. |
| 미실행 | 조작을 수행하지 않았거나, 수행했어도 증거가 없습니다. |

- 상태란이 비어 있으면 **미실행**으로 취급합니다.
- 증거 참조란이 비어 있는 항목은 통과로 기록하지 않습니다.
- 일부 단계만 수행했다면 그 시나리오는 미실행 또는 실패로 적고, 수행한 범위를 실제 관측란에 씁니다.

### 1.3 증거 종류

| 기호 | 증거 | 사용하는 경우 |
| --- | --- | --- |
| S | 스크린샷 | 정지 상태(초기 화면, HUD 값, 종료 화면, 오류 문구) |
| V | 화면 녹화 영상 | 움직임·시간 흐름(마우스 조준, 파티클, 표적 쓰러짐·재등장, 재장전 시간, 60초 진행) |
| A | 소리가 함께 녹음된 영상 | 효과음. 녹음할 수 없으면 H로 기록하고 그 사실을 적습니다. |
| C | 콘솔 기록 | DevTools Console 내용을 저장한 파일 또는 전체 화면 캡처 |
| N | 네트워크 기록 | DevTools Network의 HAR 파일 또는 요청 목록 전체 캡처 |
| H | 사람 관측 메모 | 청취, 조준 감각처럼 기록 장치로 대신할 수 없는 판단. 누가 언제 확인했는지 적습니다. |

- 파티클, 마우스 조준, 표적 애니메이션, 재장전 시간은 스크린샷 한 장으로 입증하지 않습니다. 영상(V)을 사용합니다.
- 효과음은 스크린샷이나 콘솔 기록으로 입증하지 않습니다. A 또는 H로 기록합니다.

### 1.4 통과로 기록하지 않는 방법

다음 방법으로 얻은 결과는 실제 플레이 통과가 아닙니다. 사용했다면 해당 항목을 미실행으로 두고 참고 사항에만 적습니다.

- `dispatchEvent` 등으로 만든 합성 마우스·키보드 이벤트, 자동화 도구로 보낸 입력
- DevTools Console에서 게임 상태나 규칙 설정(`roundMs`, `reloadMs` 등)을 직접 바꾸는 것
- 타이머 단축, 코드 수정, 로컬 오버라이드로 시간을 줄이는 것
- headless 브라우저나 CPU 렌더링으로 얻은 화면

FPS(초당 프레임 수)는 완료 기준이 아닙니다. 끊김이 눈에 띄면 참고 사항에만 적습니다.

## 2. 사전 조건 기록

검증 동안 저장소 파일을 바꾸지 않습니다. 모든 명령은 저장소 루트에서 실행합니다.

1. 터미널에서 다음을 실행하고 출력 전체를 기록합니다.

   ```sh
   git rev-parse HEAD
   git status --short
   ```

   `git status --short` 출력이 비어 있지 않으면 작업 트리에 변경이 있는 것입니다. 이 경우 출력 전체를 적고, 그 상태로 얻은 결과는 해당 SHA의 검증으로 보지 않습니다.
2. 같은 터미널에서 정적 서버를 시작하고 검증이 끝날 때까지 유지합니다.

   ```sh
   python3 -m http.server 8000
   ```

   포트 8000을 쓸 수 없으면 다른 포트를 쓰고, 실제 명령과 URL을 그대로 적습니다.
3. 브라우저 전체 버전을 확인합니다. Chrome은 `chrome://version`, Edge는 `edge://version`, Firefox는 `about:support`의 버전 값을 그대로 복사합니다.
4. 마우스가 연결된 데스크톱에서 수행하고, 소리를 들을 수 있도록 출력 장치를 켭니다. 인터넷에 연결되어 있어야 합니다(Three.js를 CDN에서 불러옵니다).

| 항목 | 기록 |
| --- | --- |
| 검증자 | |
| 대상 전체 SHA (`git rev-parse HEAD`) | |
| 작업 트리 변경 (`git status --short` 출력, 없으면 "출력 없음") | |
| OS 이름과 버전 | |
| 브라우저 이름과 전체 버전 | |
| 입력 장치(마우스 종류) / 소리 출력 장치 | |
| 실행 일시(시작·종료, 시간대 포함) | |
| 서버 명령 | |
| 접속 URL | |
| 녹화 도구와 소리 녹음 여부 | |

기본 접속 URL은 <http://localhost:8000/docs/index.html>입니다. `file://`로 열면 ES module이 로드되지 않으므로 사용하지 않습니다.

## 3. 브라우저 시나리오

모든 시나리오는 2장의 브라우저·URL에서 수행합니다. 시작 전에 DevTools를 열고 Network 패널의 **Disable cache**와 **Preserve log**(Firefox: **Persist Logs**)를 켭니다. 화면 녹화는 B2부터 B11까지 계속 켜 두는 것을 권장합니다.

화면 문구와 수치는 이 revision의 구현 기준입니다: 탄창 12발, 발사 간격 110 ms, 재장전 1.4초, 명중 100점, 라운드 60초, 쓰러진 표적은 약 0.7초 뒤 다른 자리에 다시 나타남.

### B1. 초기 로드와 3D 렌더링

- 전제 상태: 브라우저 탭에서 접속 URL을 연 적이 없거나, DevTools를 연 상태에서 강력 새로고침을 합니다.
- 조작 순서:
  1. DevTools Console과 Network를 비웁니다.
  2. 접속 URL을 열거나 강력 새로고침합니다.
  3. 시작 화면이 나오면 조작하지 않고 화면을 캡처합니다.
- 예상 결과:
  - 하늘색 배경의 사격장(바닥, 측벽·뒷벽, 레인 구분선, 낮은 엄폐물)이 3D로 보입니다.
  - 화면 오른쪽 아래에 총기 모델이 보이고, 사격장에 원형 표적(흰색·빨간색 동심원과 기둥)이 서 있습니다.
  - 시작 패널에 "표적 사격장" 제목과 **시작** 버튼이 보입니다.
  - HUD에 점수 `0`, 남은 시간 `60.0`, 탄약 `12 / 12`가 보입니다.
  - "WebGL을 시작할 수 없습니다" 오류 문구가 없습니다.
- 증거: S

- 조작 순서:
  1. B1 직후 Console의 오류(Error)와 경고(Warning)를 모두 기록합니다.

### B3. Network 요청 목록

- 전제 상태: B1의 새로고침을 Disable cache와 Preserve log가 켜진 상태에서 수행했습니다.
- 조작 순서:
  1. Network 패널의 필터를 **All**로 둡니다.
  2. 요청 목록 전체를 HAR로 저장하거나 캡처합니다.
  3. 각 요청의 URL, 상태 코드, 종류를 아래 표에 적습니다.
- 예상 결과:
  - 같은 출처에서 `docs/index.html`, `docs/styles.css`, `docs/js/game.mjs`, `docs/js/rules.mjs`를 상태 200(또는 304)으로 받습니다.

  - 실패 요청(4xx·5xx·차단·취소)이 있으면 모두 적습니다. 브라우저가 자동으로 요청한 `favicon.ico`의 404는 게임이 참조한 파일이 아니므로 "브라우저 자동 요청"으로 구분해 적습니다.

### B4. 실제 Pointer Lock 획득과 마우스 조준

- 전제 상태: 시작 화면.
- 조작 순서:
  1. 실제 마우스로 **시작** 버튼을 왼쪽 클릭합니다.
  2. 브라우저의 마우스 잠금 안내가 나타나는지 봅니다.
  3. 마우스를 좌우·상하로 천천히, 그다음 빠르게 끝까지 움직입니다.
- 예상 결과:
  - 시작 패널이 사라지고 커서가 숨겨지며 화면 중앙에 조준점이 보입니다. 브라우저가 마우스 잠금 안내를 표시합니다.
  - 남은 시간이 `60.0`부터 줄어듭니다.
  - 마우스 이동에 따라 시점이 같은 방향으로 회전합니다. 좌우 약 70°, 상하 약 40°에서 회전이 멈춥니다.
  - 잠금에 실패하면 "마우스 잠금(Pointer Lock)에 실패했습니다"로 시작하는 문구가 나오고 시작 화면이 유지됩니다. 이 경우 실패 문구와 재시도 결과를 적습니다.
- 증거: V (마우스를 움직이는 동안의 화면)

### B5. 명중·파티클·100점 증가, 빗나감, 쓰러진 표적의 중복 점수

- 전제 상태: 라운드 진행 중(B4 직후), 탄약이 남아 있음.
- 조작 순서:
  1. 조준점을 표적 원판에 맞추고 한 번 클릭합니다.
  2. 표적이 쓰러지는 동안 같은 자리를 바로 한 번 더 클릭합니다.
  3. 표적이 없는 벽이나 바닥을 한 번 클릭합니다.
  4. 엄폐물 뒤 표적이 있으면 엄폐물에 가려진 부분을 한 번 클릭합니다.
  5. 약 1초 기다려 표적이 다른 자리에 다시 나타나는지 봅니다.
- 참고: 직전 발사 후 110 ms 안의 클릭은 발사되지 않습니다. 각 클릭 사이에 짧게라도 간격을 둡니다.
- 예상 결과:
  - 1: 총구 섬광과 반동이 보이고, 점수가 정확히 100 오르며, 조준점에 명중 표시가 잠깐 나타나고, 표적이 뒤로 쓰러지며 명중 지점에서 빨강·흰색·노랑 파티클이 튑니다.
  - 2: 탄약은 한 발 줄지만 점수는 오르지 않습니다.
  - 3: 탄약은 한 발 줄고 점수는 그대로입니다. 맞은 자리에 어두운 탄착 표시와 먼지 파티클이 보였다가 약 1초 뒤 사라집니다.
  - 4: 점수가 오르지 않습니다(엄폐물에 맞은 탄착 표시).
  - 5: 쓰러진 표적이 약 0.7초 뒤 이전과 다른 자리에 일어섭니다.
  - 모든 클릭에서 탄약이 클릭당 한 발씩 줄어듭니다.
- 증거: V (명중 전후 HUD 점수가 보이는 영상), 필요하면 S

### B6. 12발 소진, 빈 탄창, `R` 재장전

- 전제 상태: 라운드 진행 중. 처음 클릭 전에 `R`을 눌러 재장전해 탄약을 `12 / 12`로 맞춥니다(가득 찬 상태의 `R`은 아무 동작도 하지 않습니다).
- 조작 순서:
  1. 약 0.5초 간격(110 ms보다 충분히 긴 간격)으로 한 번씩 총 12번 클릭하며 탄약 표시를 봅니다.
  2. 탄약이 `0 / 12`가 된 뒤 두 번 더 클릭합니다.
  3. `R`을 한 번 누릅니다.
  4. 재장전 막대가 보이는 동안 여러 번 클릭합니다.
  5. 재장전이 끝난 뒤 한 번 클릭합니다.
- 예상 결과:
  - 1: 클릭마다 탄약이 1씩 줄어 `0 / 12`가 됩니다. 탄약 표시는 3발 이하에서 경고 색으로 바뀝니다. 0이 되면 상태 문구 "R 키로 재장전"이 보입니다.
  - 2: 발사되지 않습니다(섬광·반동·점수 변화 없음). 상태 문구 "탄창이 비었습니다 — R 재장전"이 잠깐 보입니다.
  - 3: 상태 문구 "재장전 중…"과 재장전 막대가 나타나고 총이 내려갔다 올라옵니다.
  - 4: 발사되지 않고 탄약이 `0 / 12`로 유지됩니다.
  - 3에서 약 1.4초 뒤 탄약이 `12 / 12`가 되고 막대가 사라집니다. 영상 시각으로 `R` 입력부터 `12 / 12` 표시까지 시간을 잽니다.
  - 5: 정상 발사되어 `11 / 12`가 됩니다.
- 증거: V (탄약 HUD가 보이는 영상, 재장전 시간 측정용)

### B8. `Esc` 정지와 계속하기

- 전제 상태: 라운드 진행 중. 좌우로 흔들리는 표적이 하나 이상 화면에 보이도록 조준합니다.
- 조작 순서:
  1. 남은 시간을 기록하고 `Esc`를 누릅니다.
  2. 일시 정지 화면에서 5초 이상 기다립니다.
  3. `Esc`를 누른 직후(1초 안) **계속하기**를 한 번 눌러 봅니다. 거부되면 문구를 기록하고 2초 이상 기다린 뒤 다시 누릅니다.
  4. 재개 후 남은 시간과 흔들리는 표적의 위치를 봅니다.
- 예상 결과:
  - 1: 마우스 잠금이 풀리고 "일시 정지" 패널과 **계속하기** 버튼이 나타납니다.
  - 2: 남은 시간 표시와 흔들리는 표적이 멈춰 있습니다. 클릭해도 발사되지 않습니다.
  - 3: 브라우저가 재잠금을 거부하면 "마우스 잠금(Pointer Lock)에 실패했습니다"로 시작하고 "잠시 후 버튼을 다시 눌러 주세요."로 끝나는 문구가 보이고 일시 정지 화면이 유지됩니다. 잠시 후 다시 누르면 재개됩니다. 거부되지 않았다면 "거부 없음"으로 적습니다.
  - 4: 남은 시간이 정지 직전 값에서 이어서 줄어듭니다. 흔들리는 표적이 정지 직전 위치에서 이어서 움직이고 순간 이동하지 않습니다.
- 증거: V (정지 전·중·후 HUD와 표적), 오류 문구는 S

### B9. 실제 60초 종료

- 전제 상태: 새 라운드 시작 직후(남은 시간 `60.0`). 이 라운드에서는 일시 정지하지 않는 것을 권장합니다. 정지했다면 정지 구간을 적습니다.
- 조작 순서:
  1. 시작 시각을 영상 시각으로 기록하고, 남은 시간이 0이 될 때까지 평소처럼 플레이합니다.
  2. 종료 화면이 나오면 기록합니다.
  3. 종료 화면에서 화면을 여러 번 클릭하고 `R`을 누릅니다(**다시 시작** 버튼은 누르지 않습니다).
- 예상 결과:
  - 남은 시간은 10초 이하에서 경고 색으로 바뀌고, 활성 플레이 시간 60초에 `0.0`이 됩니다.
  - 마우스 잠금이 풀리고 "라운드 종료" 패널, "최종 점수 N", "명중 h / 발사 s (명중률 x%)", **다시 시작** 버튼이 나타납니다. 최종 점수는 마지막 HUD 점수와 같습니다.
  - 3: 점수·탄약·최종 점수가 바뀌지 않습니다.
  - 시작 시각부터 종료 화면까지 영상 시간은 60초에 정지 구간을 더한 값과 거의 같습니다.

## 7. 문제가 생겼을 때

- 장면이 보이지 않음: Network에서 `three.module.js` 요청의 상태를 확인하고 Console 오류를 적습니다. CDN에 연결할 수 없으면 B1을 실패로 적고 이후 시나리오는 미실행으로 둡니다.
- `file://` 주소로 열림: 2장의 서버 명령과 URL로 다시 엽니다.
- 시작 버튼을 눌러도 잠금이 안 됨: 오류 문구를 S로 남기고 잠시 후 다시 누릅니다. 계속 실패하면 B4를 실패로 적습니다.
- 소리가 들리지 않음: 브라우저 탭 음소거와 OS 출력 장치를 확인한 뒤 다시 시도하고, 확인한 내용을 4장에 적습니다.
- 발견한 결함: 재현 순서, 기대 결과, 실제 결과, 증거 참조를 함께 제출합니다. 검증 중에 코드를 고치지 않습니다.
